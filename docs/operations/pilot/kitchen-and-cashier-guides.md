# Kitchen and Cashier Quick Guides (proposed)

Assumes you have already signed in — see
`docs/operations/pilot/staff-quick-start.md`.

## Kitchen

1. Open **Kitchen**. New items appear grouped by order, with each item's
   name, quantity, note, and elapsed time since the order was submitted.
2. Start an item when you begin preparing it.
3. Mark an item ready when it is done. Once every item in an order is ready,
   the order is offered for serving to general staff — you do not need to
   tell anyone directly.
4. If the screen shows a stale banner, it means the display could not
   confirm it is current — wait for reconnect or refresh; do not act on a
   stale screen for a live order.

## Cashier / payments

1. Open **Payments**. Visible bill requests come from tables that asked to
   pay — no order number needs to be typed in.
2. Open the bill request, confirm the amount, and record the payment method
   (cash or card).
3. For a refund or correction, open the order's payment history directly
   from the visible order/payment list — never type in an order ID.
4. Completing an order that is not fully paid requires an explicit
   confirmation step; use it only when your manager's policy allows it.
5. A duplicate tap on "record payment" is safe — the system recognizes the
   repeated action and will not charge or record twice.

## Common to both

- Every action that changes money, an order, or a table shows a clear
  pending → succeeded/failed state. Do not assume success until you see the
  confirmation.
- If your permissions change while you're signed in (for example, a role
  update), the app tells you your session ended and asks you to sign in
  again — this is expected, not a bug.
